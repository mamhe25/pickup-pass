PICKUPPASS PHASE 3 — CUMULATIVE UPDATE 4
==========================================

Copy everything in this folder into the root of your existing PickupPass - Copy project and choose Replace/Overwrite.

Update 4 adds billing periods, trial expiration handling, renewal controls, grace periods, cancellation-at-period-end, and automated subscription-state enforcement. It is cumulative and includes all earlier Phase 1, Phase 2, and Phase 3 Update 1–3 replacement files.

- PHASE3_BILLING_LIFECYCLE_NOTES.md

DEFAULT LIFECYCLE
- Trial expires -> past_due + 7-day grace
- Grace expires -> cancelled optional feature access
- Active period ends + auto-renew -> next 30-day period
- Active period ends + cancel-at-period-end -> cancelled
- Core QR pickup remains available regardless of subscription feature state

No new Firestore composite index is required.

IMPORTANT: run your normal backend and Android build/tests after replacement before production deployment.

NEW IN UPDATE 9 — SCHEDULED ANNOUNCEMENTS
- School admins can Send Now or Schedule an announcement.
- Future announcements are stored as durable Firestore jobs.
- Server scheduler sends due announcements automatically.
- Transactional job claiming supports multiple Cloud Run/backend instances.
- 10-minute processing lease recovery.
- Announcement history with scheduled/sent/cancelled/failed states.
- Cancel a pending scheduled announcement.
- Sent recipient count.
- Scheduling/delivery/cancellation/failure audit records.
- Title/body production limits.

REQUIRED AFTER REPLACEMENT
From pickup-pass-system run:
  firebase deploy --only firestore:indexes

This deploys the new composite index:
  broadcastJobs: status ASC, scheduledAt ASC

OPTIONAL ENVIRONMENT VARIABLE
  BROADCAST_SCHEDULER_MS=30000
Default is 30 seconds.

CORE PICKUP FLOW IS UNCHANGED
A guardian with a valid QR can still go directly to pickup staff. No queue or arrival check-in is required.

PHASE 3 UPDATE 6 — INVOICE PDF, BILLING EMAIL & PAYMENT WEBHOOK FOUNDATION
- Adds a school billing profile (name, email, address, tax/registration ID).
- New invoices snapshot the billing profile so historical PDFs do not change when a school later edits its profile.
- Adds on-demand PDF invoice generation using Apache PDFBox 3.0.8.
- Master Admin can save a PDF from Android through the system document picker.
- Master Admin can email an invoice as a PDF attachment through configured SMTP.
- Email delivery metadata is tracked without making a post-send metadata failure look like a failed email.
- Adds provider-neutral payment webhook adapter architecture.
- Initial adapter: generic-hmac with HMAC-SHA256 signature verification, 5-minute replay window, event-id idempotency, exact invoice amount/currency validation, and transactional invoice payment updates.
- Public webhook route: POST /api/webhooks/payments/{provider}. Only the webhook route is unauthenticated; cryptographic verification is mandatory.
- Adds payment webhook rate limiting.
- New collection: paymentWebhookEvents (direct document-id access; no new composite index required).
- Existing billingInvoices composite index from Update 5 is still required.
- Core student QR pickup is never dependent on SMTP, PDF generation, or payment webhooks.

PRODUCTION BILLING EMAIL
Configure MAIL_HOST / MAIL_PORT / MAIL_USERNAME / MAIL_PASSWORD and BILLING_FROM_EMAIL.
If billing email is not configured, invoice PDF download still works and the email endpoint returns a controlled service-unavailable response.

PAYMENT WEBHOOK SECURITY
The generic-hmac adapter is intentionally provider-neutral. Configure PAYMENT_WEBHOOK_GENERIC_SECRET with a long random secret.
Do not expose that secret in the Android app. Signature verification happens only on the backend.
See PHASE3_BILLING_DELIVERY_WEBHOOK_NOTES.md for the normalized webhook contract.
