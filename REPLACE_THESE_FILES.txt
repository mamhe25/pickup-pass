PICKUPPASS PHASE 3 — CUMULATIVE UPDATE 12
==========================================

This is a CUMULATIVE replacement pack. It contains the PickupPass replacement files from the earlier Phase 1/2/3 updates plus Phase 3 Update 12.

HOW TO APPLY
1. Stop the backend and close/stop the Android app build if running.
2. Extract the protected archive.
3. Open the PickupPass_Phase3_Cumulative_Update_12 folder.
4. Copy everything inside it into the ROOT of your existing "PickupPass - Copy" project.
5. Choose Replace / Overwrite when Windows asks.
6. Do not delete project files that are not present in this replacement pack.
7. Review PHASE3_STARTUP_BACKUP_DATA_EXPORT_NOTES.md before enabling backup/export controls.
8. Keep FIRESTORE_DR_ENABLED=false until the platform owner intentionally configures cloud IAM.
9. Run your normal backend tests and Android build before production deployment.



UPDATE 12 — STARTUP BACKUP MODE & OPTIONAL TENANT DATA EXPORT
-------------------------------------------------------------
- Changes the recommended native Firestore protection strategy to startup-first rather than enterprise-first.
- Free safeguards: database delete protection only; PickupPass creates no scheduled backup or PITR.
- Startup backup: delete protection + one daily native backup with 7-day default retention; no PITR or weekly backup is created.
- Growth protection remains opt-in: daily + weekly backups, PITR, and delete protection.
- Native Firestore backup/restore controls remain MASTER ADMIN / PLATFORM OWNER only because they affect shared infrastructure, IAM, billing, and all tenants.
- School admins do NOT receive cloud backup, PITR, or restore privileges.
- Adds optional school-admin tenant data export. It is OFF by default per school and can only be enabled/disabled by the platform owner.
- Platform owner can always export a selected tenant for support/recovery.
- Tenant exports are generated on demand and downloaded directly to the selected device location; PickupPass does not create a recurring Cloud Storage copy.
- Export excludes platform billing/security internals and redacts secret/token-like fields.
- Export safety defaults: 25,000 documents and 50 MiB archive size.
- Existing stronger cloud protection is never silently disabled when a startup/free profile is selected.

UPDATE 11 — BACKUP, DISASTER RECOVERY & DATA RETENTION
-------------------------------------------------------
- Adds Master Admin Backup & Disaster Recovery control/health center.
- Uses native Firestore scheduled backups/PITR/delete protection instead of application-level document copying.
- Original Update 11 growth profile: daily backup 14 days, weekly backup 84 days, PITR enabled, database delete protection enabled. Update 12 supersedes the startup recommendation.
- Backup age health threshold defaults to 48 hours and is configurable.
- DR integration is OFF by default until cloud IAM/project configuration is intentional.
- Restore drills are independently OFF by default.
- Recovery drills restore a READY backup to a separate generated Firestore database; production is never overwritten or switched automatically.
- Restored database source metadata is checked against the selected backup before a drill is marked verified.
- Long-running PITR/delete-protection updates are tracked asynchronously so the mobile request does not wait for the cloud operation to finish.
- Adds six-hour non-blocking recovery-health snapshot by default.
- Adds seven-day expiresAt to idempotency records so server-side Firestore TTL can be used safely.
- Surfaces retention guardrails: ephemeral technical records can use TTL; exit logs, audit records, and financial records are not automatically deleted.
- Production startup validates DR project configuration when DR is enabled.
- DR/health failures remain completely outside guardian QR verification, student release, and exit-log success.

UPDATE 10 — MASTER ADMIN AUDIT & SECURITY CENTER
--------------------------------------------------
- Adds a Master Admin Security Center with severity metrics, active alerts, acknowledgment/resolution workflow, and recent privileged actions.
- Privacy-preserving request correlation using HMAC fingerprints; raw client IP addresses and tokens are not stored.
- Repeated invalid Firebase token attempts are aggregated in 15-minute windows before escalating to a high-severity alert.
- Revoked device attempts produce deduplicated security alerts.
- Privileged endpoint access-denied events produce security alerts for authenticated users.
- Protected API rate-limit events are surfaced without storing request bodies or credentials.
- Master Admin can acknowledge/resolve alerts.
- Master Admin can revoke all device sessions and Firebase refresh tokens for a UID with a required reason.
- Existing systemAuditEvents are shown as recent privileged-action history.
- Production startup now requires a separate SECURITY_FINGERPRINT_SECRET (32+ random characters).
- Security telemetry write failures are non-blocking and remain outside the student release transaction.

UPDATE 9 — SAAS OPERATIONS HEALTH + RECONCILIATION DASHBOARD
-------------------------------------------------------------
- Adds a Master Admin Operations Health dashboard.
- Tenant health states: Healthy / Attention Needed / Billing Risk / Over Quota / Suspended.
- Materializes deduplicated operational alerts instead of recalculating all rules on every screen open.
- Immediate GCash payment-review alert when a school submits a manual GCash payment notice.
- GCash confirmation/rejection resolves/recomputes the affected tenant.
- Overdue and due-soon invoice alerts.
- Trial, subscription-period, and grace-period expiry alerts.
- Near-quota warning (default 90%) and over-quota detection for students/staff/campuses.
- Billing invoice/receipt/reminder email failure tracking with automatic alert resolution after a successful retry.
- Tenant-scoped health refresh after billing/subscription/status/quota mutations.
- Hourly subscription lifecycle and invoice-overdue transitions refresh affected tenant health immediately.
- Daily full platform health reconciliation by default, stale-view lazy refresh, plus a manual Refresh Operations action.
- Operational alerts remain outside the student QR verification/release transaction path.
