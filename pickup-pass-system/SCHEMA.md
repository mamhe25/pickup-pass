# Firestore Schema Reference

This is the complete, current shape of every collection. Fields marked
*(optional)* may be absent on older or not-yet-touched documents rather
than present-but-null — always code defensively around their absence.

Authorization source of truth is **Firebase Auth custom claims**
(`role`, `schoolId`), set server-side by the provisioning services below —
never trust a client-supplied role or schoolId anywhere. The same two
values are mirrored onto the `users/{uid}` document purely for querying/
display convenience; both are always written together in the same
operation, so they can't drift apart as long as account creation goes
through `GuardianProvisioningService` or `StaffProvisioningService` (i.e.
never create a Firebase Auth user directly without also going through one
of those).

> **No Cloud Storage bucket is used anywhere in this project.** As of
> Feb 3, 2026, Cloud Storage for Firebase requires the pay-as-you-go Blaze
> plan even for entirely free-tier usage. Both `photoUrl` and `logoUrl`
> fields hold small, resized/compressed images encoded as base64 **data
> URIs stored directly in the document** (`data:image/jpeg;base64,...`),
> not links to an external file. This keeps everything on the free Spark
> plan, at the cost of images being pulled along with every read of that
> document rather than being independently cacheable behind a CDN URL —
> a fine trade for a once-per-user avatar or once-per-school logo.

## `schools/{schoolId}`

Document ID is auto-generated by Firestore (`POST /api/master-admin/schools`).

| Field | Type | Notes |
|---|---|---|
| `schoolName` | string | |
| `status` | string | `"active"` \| `"suspended"` |
| `statusUpdatedAt` | timestamp | *(optional)* set on first status change |
| `createdAt` | timestamp | |
| `logoUrl` | string \| null | *(optional)* base64 data URI, e.g. `"data:image/png;base64,..."` — not a Storage URL, see note below |
| `logoUpdatedAt` | timestamp | *(optional)* |

## `users/{uid}`

Document ID = the Firebase Auth UID.

| Field | Type | Notes |
|---|---|---|
| `role` | string | `"master_admin"` \| `"school_admin"` \| `"teacher"` \| `"parent"` |
| `schoolId` | string | **absent** for `master_admin` (a global role) |
| `email` | string | |
| `displayName` | string | |
| `photoUrl` | string \| null | *(optional)* base64 data URI (see note below); face-verification photo, mainly parents but any role can have one |
| `isActive` | boolean | flipped to `false` for every user of a school when that school is suspended |
| `createdAt` | timestamp | |
| `fcmTokens` | string[] | *(optional)* one entry per signed-in device, for push notifications |

| Field | Type | Notes |
|---|---|---|

| `fullName` | string | |
| `grade` | string | |
| `section` | string | |

| Field | Type | Notes |
|---|---|---|

| `isPrimary` | boolean | *(optional on legacy records)* current records set this at guardian creation. If absent on a historical first `guardianUids` relationship, the application preserves that guardian as the legacy primary; explicit `false` is never promoted. |
| `addedBy` | string | uid of whoever added this guardian |
| `addedAt` | timestamp | |

## `pickupTokens/{nonce}`

Document ID = the token's nonce (a UUID). One doc per QR code ever issued —
this is the source of truth for single-use + time-window enforcement; the
JWT encoded in the QR itself is only a tamper-evident pointer into this
collection.

| Field | Type | Notes |
|---|---|---|
| `schoolId` | string | |
| `studentId` | string | |
| `parentUid` | string | which guardian generated this specific pass |
| `nonce` | string | duplicated from the doc ID for query convenience |
| `used` | boolean | flipped to `true` on approval, or immediately if superseded/revoked |
| `issuedAt` | timestamp | server timestamp at generation |
| `dismissalDeadline` | timestamp | `issuedAt + 2h`; independent of the JWT's own short expiry |
| `usedAt` | timestamp | *(optional)* set on approval |
| `invalidatedReason` | string | *(optional)* `"superseded_by_new_token"` \| `"guardian_removed"` |

## `exitLogs/{logId}`

Auto-ID. **Append-only** — Firestore rules disallow update/delete entirely,
so this is an immutable audit trail.

| Field | Type | Notes |
|---|---|---|
| `schoolId` | string | |
| `studentId` | string | |
| `parentUid` | string | which guardian actually picked up |
| `verifiedByUid` | string | staff member who tapped Approve |
| `timestamp` | timestamp | |
| `method` | string | currently always `"qr_scan"` |

## How a document gets created (who writes what)

| Collection | Created by | Endpoint |
|---|---|---|
| `schools` | master_admin | `POST /api/master-admin/schools` |
| `users` (master_admin) | bootstrap (once) | `POST /api/bootstrap/master-admin` |
| `users` (school_admin / teacher) | master_admin | `POST /api/master-admin/schools/{schoolId}/staff` |
| `users` (teacher, own school only) | school_admin | `POST /api/school-admin/staff` |
| `students` (roster record, `guardianUids: []` initially) | teacher/school_admin | `POST /api/teacher/students` |
| `users` (parent) + initial `students.guardians` entry | teacher/school_admin | `POST /api/teacher/register-parent` |
| `students.guardians` (backup guardian) | parent | `POST /api/parent/add-guardian` |
| `pickupTokens` | parent | `POST /api/parent/generate-token` |
| `exitLogs` | teacher/school_admin (via approval) | `POST /api/pickup/approve` |

Full request/response shapes for each are in the main `README.md` endpoint
table.

## Firestore security rules

See `firebase/firestore.rules` for the actual enforced rules (schoolId
isolation, guardian-array membership checks, append-only exit logs, etc).
These are the real enforcement layer — the backend's own checks are
defense in depth on top of them, not a substitute for them, since Firestore
is also reachable directly from client SDKs for read paths. Document-size
limits (1MiB) are what implicitly caps how large an embedded avatar/logo
can be — there's no separate rule for it the way `storage.rules` used to
enforce a 100KB cap, since that file isn't deployed by default anymore
(see the note above about Cloud Storage's Blaze requirement).
